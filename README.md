# fdlossless — 函数依赖下的无损分解见证与最优选择

离线数据库理论工具库：给定关系模式、函数依赖集（FD）和一个分解，计算最小覆盖、
候选键、各子关系上的完整投影依赖，判定依赖保持，并用符号表 chase 判定无损连接；
若有损，输出一个经过自检的小反例。在此之上，`select_decomposition` 在给定的
候选子关系、必须保留的属性组与非负整数成本下，枚举选出一个**覆盖属性、无损且
保持依赖**的最优分解（先比总成本，再比关系数，最后比属性字典序），无解时给出
分类原因。全部核心算法（闭包、最小覆盖、候选键、投影、chase、反例构造、子集
枚举选优）均为本仓库从零实现，不调用任何第三方同类实现。

## 环境

- Python 3.14.7，Linux 原生运行。
- 仅使用标准库，安装 Python 后无需安装任何其他依赖（`requirements.txt` 为空注释）。
- 核心、测试、演示全部离线：不需要账号、网络、数据库、Docker 或任何外部服务。

## 接口

### 分解见证：`analyze`

```python
from fdlossless import analyze

result = analyze(
    attributes,      # 属性名 iterable[str]，1..12 个，唯一、非空
    FDs,             # [(lhs, rhs), ...]，左右均为属性名集合；空决定项合法，rhs 非空
    decomposition,   # [子关系属性集合, ...]，非空、互不相同，并集必须等于 attributes
    *, step_budget=100_000,  # chase 合并步数预算（int，拒绝 bool/NaN/Inf/负数）
)
```

`analyze` 是纯函数，返回不可变的 `AnalysisResult`：

| 字段 | 含义 |
|---|---|
| `minimal_cover` | 最小覆盖，`FD(lhs=tuple, rhs=str)` 元组 |
| `candidate_keys` | 候选键，按大小再按字典序排序 |
| `projections` | 每个子关系上的完整投影依赖（每个被蕴含 FD 的最小左部生成集） |
| `dependency_preserving` | 依赖保持判定（投影之并是否蕴含全部原 FD） |
| `lossless` | 无损连接判定（chase 终止后是否存在全可区分符号行） |
| `chase_log` | 逐步等同记录 `ChaseStep`（所用 FD、行对、列、保留/替换符号、可读说明） |
| `counterexample` | 有损时为 `CounterExample`：满足全部 FD 的小实例、各投影、寄生元组及说明；无损时为 `None` |

依赖保持与无损连接是**独立计算**的两个判定，互不替代（有测试覆盖
“保持但有损”与“无损但不保持”两个方向）。

### 最优分解选择：`select_decomposition`

```python
from fdlossless import select_decomposition

result = select_decomposition(
    attributes,       # 属性名 iterable[str]，1..6 个，唯一、非空
    FDs,              # 同 analyze
    candidates,       # 候选子关系集合列表，1..8 个，非空、互不相同（属性须已知）
    required_groups,  # 必须整体落在某个选中子关系内的属性组列表；可为空
    costs,            # 与 candidates 一一对应的非负整数成本（拒绝 bool/float/NaN/负数）
    *, step_budget=100_000,  # 每个被检查子集的 chase 预算
)
```

纯函数，枚举候选的全部非空子集（至多 2⁸−1=255 个），保留同时满足以下条件者：

1. **覆盖**：选中子关系之并等于全部属性；
2. **必保组**：每个 `required_groups` 中的属性组包含于某一个选中子关系；
3. **无损**：符号表 chase 判定；
4. **保持依赖**：各子关系投影之并蕴含全部原 FD。

在全部合格子集中，按 `(总成本, 关系数, 属性字典序)` 取唯一最优；字典序比较把
每个子关系按属性名升序排列后，再比较子关系元组的升序排列（与输入顺序无关）。
返回不可变的 `SelectionResult`：

| 字段 | 含义 |
|---|---|
| `feasible` | 是否存在合格分解 |
| `chosen` | 可行时：选中的子关系（属性按名升序）；无解时为空元组 |
| `total_cost` / `relation_count` | 可行时的总成本与关系数；无解时为 `None` |
| `analysis` | 可行时对所选分解运行公开 `analyze` 的完整 `AnalysisResult`（含 chase 日志、投影、候选键）；无解时为 `None` |
| `reason` | 无解时的分类说明（见下）；可行时为 `None` |
| `subsets_considered` | 实际枚举的非空子集数 `2^len(candidates)-1` |
| `attributes` / `fds` / `candidates` / `required_groups` / `costs` | 规范化后的输入回显 |

无解不是异常：`feasible=False` 时 `reason` 按层级给出分类——
（a）没有任何子集覆盖全部属性；（b）覆盖子集都不能同时容纳全部必保组
（并列出没有任何候选能容纳的组）；（c）覆盖且满足必保组的子集中，
分别统计“仅无损但不保持依赖”“仅保持依赖但有损”“两者都不满足”的数量。

## 错误语义

- `InvalidInputError`（`ValueError` 子类）：非法输入一律拒绝并给出可定位信息
  （如 `FDs[2].lhs[0]: unknown attribute 'X'`、
  `costs[1]: costs must be non-negative, got -2`），不做静默纠正。
  数值位置拒绝 NaN/Infinity；整数参数（`step_budget`、各项 `costs`）拒绝 bool。
- `SearchBudgetExhausted`：chase 合并预算耗尽。这**不是**有损证明也**不是**
  无解证明，与“已证明有损 / 已枚举完无解”严格区分；加大 `step_budget` 重跑即可。
- `analyze`、`select_decomposition` 均为无状态纯函数：所有输入校验先于任何计算，
  失败不会留下任何部分变更，也不影响后续调用。

## 输入上限

- `analyze`：属性数 ≤ 12（`MAX_ATTRIBUTES`）。
- `select_decomposition`：属性数 ≤ 6（`SELECT_MAX_ATTRIBUTES`），
  候选子关系数 ≤ 8（`MAX_CANDIDATES`），因此最多枚举 255 个子集。
- 子关系个数、FD 个数在 `analyze` 中无单独上限，受属性数与 `step_budget` 间接约束。

## 精度口径

本库不产出任何浮点结果：所有输出为精确的符号、布尔、字符串与整数常量，
不存在误差区间，也不存在用宽容差掩盖边界的问题。成本与总成本均为整数精确比较。

## 设计取舍

- **完整投影依赖的表示**：对每个子关系 S、每个 a∈S，枚举所有使 a∈X⁺ 成立的
  极小左部 X⊆S。该集合是投影的完整生成集（投影中每个 FD 的左部都包含某个
  列出的 X），同时避免列出非极小冗余左部。
- **候选键排序**：键内属性按名字字典序排列，键之间按 (大小, 字典序) 排序，确定性输出。
- **chase 符号**：可区分符号按列命名，非可区分符号为 `b<行>_<列>`（1 起始）；
  合并时保留“更优”符号（可区分优先，其次行号小者），全表替换并记录日志。
- **反例构造**：最终未合并表逐行映射为常量元组（可区分符号→列号，
  非可区分符号→新常量），返回前自检：实例满足全部 FD、寄生元组属于各投影的
  自然连接且不在实例中。
- **选择器枚举与复用**：必保组与成本规模小（≤6 属性、≤8 候选），直接枚举全部
  子集即可精确取最优，无需启发式；投影只依赖候选本身，逐子集判定前先缓存。
  合格子集的判定直接复用 `core` 的闭包/投影/chase；最终对所选分解再跑一次公开
  `analyze`，返回完整可复验见证。无解时逐子集分类计数，区分失败层级。
- **有限子集声明**：本库只实现本题契约（FD、无损/依赖保持判定、受约束子集选优），
  不宣称兼容完整关系数据库理论工具链或任何行业标准。

## 已知限制

- 属性数上限：`analyze` 12、`select_decomposition` 6；投影与候选键为子集枚举，
  复杂度随属性数指数增长（上限内可秒级完成）。
- 选择器的最优性仅在“给定候选集合”意义下成立，不生成候选之外的新子关系，
  也不做 3NF/BCNF 合成；成本模型为逐候选非负整数可加成本。
- chase 预算耗尽时抛 `SearchBudgetExhausted` 而非给出判定（默认预算 100000 步，
  对 6 属性 8 候选的枚举远远足够）。
- 反例常量为整数编码，仅保证区分性，不对应任何业务语义。

## 验证与演示

```bash
python -m unittest discover -s tests -v   # 单元测试 + 两路穷举交叉核对
python demo.py                            # 固定输入演示，1 秒内完成
```

- `tests/test_exhaustive.py`：独立参考实现——对 {A,B,C} 上全部 ≤2 条的 FD 集
  （79 个）与全部二部覆盖分解加三单例分解（13 种），穷举二值域 {0,1} 上的
  全部 256 个关系，按定义判定无损性并与 chase 判定逐一比对；对每个有损情形
  独立验证反例（满足 FD、寄生元组在连接中且不在实例中）。参考实现不调用被测核心。
- `tests/test_selection.py`：选择器的手算用例——成本优先于关系数、全平局时
  关系数与属性字典序决胜、必保组强制选择高成本方案、无解的分类计数、
  预算耗尽与全部非法输入定位，以及失败调用不留状态。期望值均手算给出。
- `tests/test_selection_exhaustive.py`：选择器的独立暴力交叉核对——8 个 FD 集 ×
  4 种候选池 × 3 种必保组配置 × 4 组确定性成本（384 个场景），参考实现独立
  枚举二值域全部关系判无损、独立闭包判依赖保持，逐子集求最优并与选择器的
  可行性、选中方案、成本及无解分类计数逐一比对。参考实现不调用被测核心。
- `demo.py`：真实计算并打印一个无损（但不保持依赖）的完整可复验 chase、
  一个有损反例、一个 `analyze` 输入边界拒绝（13 个属性），以及选择器的
  正常最优选择、无解分类说明和一个实际触发的非法成本拒绝。
